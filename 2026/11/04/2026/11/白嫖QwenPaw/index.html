3️⃣ Day 1：本地装 Tailscale

执行：winget install Tailscale.Tailscale → 装上 1.104.5，服务自动运行，托盘程序正常。

坑：tailscale up 首次需要浏览器授权，命令会打印一条 https://login.tailscale.com/a/xxxx 链接，点开登录即可（链接约 10 分钟过期，过期重跑 tailscale up）。

验证结果：

  • ✅ 容器节点早就加入过 tailnet：qwenpaw-sbs-prod-4lx77 = 100.68.168.78
  • ✅ ping 通（64ms，走 DERP 新加坡中继）
  • ⚠️ direct connection not established —— 容器无公网 IP，UDP 打洞失败，永远走中继
  • ❌ 22 端口 Connection refused —— 容器里根本没装 sshd

4️⃣ Day 2（11-04）：-C "Muke@win10" 是邮箱吗

结论：不是。ssh-keygen -C 只是注释，纯标签，不参与认证、不校验格式、不发往任何服务。

建议填「设备-用途-日期」这类能区分来源的字符串。改注释只需编辑 .pub 文件行尾，不影响密钥本体。

6️⃣ Day 2：想装 Docker —— ⛔ 此路不通（最大坑）

做了完整的可行性探测，结论：这台容器装不了标准 Docker，也不适合 Podman。

检测项 结果 影响
CapEff 缺 CAP_SYS_ADMIN、CAP_NET_ADMIN dockerd 起不来
/dev/fuse 不存在 fuse-overlayfs 不可用
/dev/net/tun 不存在 slirp4netns 网络模式失败
/sys/fs/cgroup tmpfs、无 controllers cgroup 无法托管
seccomp / userns 关闭 / 可用 唯一的好消息

实测过程：装上 Podman 4.3.1 后，podman run 卡在 fuse-overlayfs: cannot mount: No such file or directory；改 vfs 驱动 + --network=host 也受网络层限制。

最终建议：要跑镜像去 HK 轻量服务器（真 VPS、root 完整），这台 2C4G 无 Swap 的机器直接 apt 装运行时（.NET SDK / Python / Node）最划算。

7️⃣ Day 2：Xshell 报「所选的用户密钥未在远程主机上注册」

这是本次排查最曲折的坑，根因有三个，逐层剥开：

坑 A：Xshell 勾了「使用身份验证配置文件」但选的是 <未指定>

从截图发现：☑ 使用身份验证配置文件(A) → <未指定>，且 设置(S)... 按钮是灰的。
该模式下 Xshell 忽略手工配置的认证方式，等于什么密钥都没提供。

✅ 修复：取消勾选 → 设置(S)... 变可点 → 在里面选用户密钥。

坑 B：authorized_keys 那一行带 CRLF（Windows 换行符）

服务端排查时发现：

OpenSSH 会整行拒绝带 \r 的公钥。表现为：公钥登录失败、密码登录正常。

✅ 修复：sed -i 's/\r$//' /root/.ssh/authorized_keys

坑 C：本地密钥和服务端公钥根本不是一对（指纹不匹配）

位置 指纹 注释
本地 ~/.ssh/id_ed25519 SHA256:KFwg... xxxxxxx
服务端 authorized_keys SHA256:u4Nk... Muke@win10

这才是 Xshell 报”未注册”的准确原因 —— 它没说错，服务器上确实没有本地这把钥匙的公钥。

✅ 修复：把当前本地公钥追加进 authorized_keys（注意传输时去 \r），ssh-keygen -lf 两边指纹一致后恢复。

经验总结：

  1. 公钥认证失败先跑 ssh -vv，看 Offering public key 后服务端是否接受
  2. 两边指纹用 ssh-keygen -lf 对比，比肉眼比对 base64 靠谱
  3. cat -A authorized_keys 一眼看出 CRLF
  4. 公钥从 Windows 传到 Linux，永远先 tr -d '\r'

附：临时密码（排障用，已实测可用）

8️⃣ Day 2~3：QwenPaw 网页对话「老是断开、要不停重开窗口」

结论：QwenPaw 服务端没崩（进程连续运行 47h+，28 次对话流全部 has_response=True 正常结束）。断的是浏览器 ↔ 后端的长连接，四层原因：

# 原因 证据
1 平台反向代理空闲超时（主因）：模型思考/等审批时无数据下发，约 60s 被掐 容器内无反代进程，连接由 platform.agentscope.io 外部代理接管；SSE 单流最多推 6869 个事件
2 容器出网 NAT 偶发重置 tailscaled 重连 34 次，PollNetMap: unexpected EOF 多次
3 审批 5 分钟超时：内核 5.10 < 5.13 无 Landlock → 每条 Bash 都要人工审批，人离开页面就 decision=timeout → 任务被 cancel sandbox not available 告警 29 次
4 上下文频繁压缩 + session 文件读失败：单会话累计 prompt 178 万 / 窗口 100 万 / 阈值 80%；session 状态在 NAS 上偶发读不到 Session file does not exist 多条

✅ 最有效的解法：Tailscale 直连，绕开平台反代

浏览器直接开 http://100.68.168.78:8088（实测 HTTP 200，返回完整 QwenPaw Console 页面）

  • 不经过 platform.agentscope.io，无空闲超时
  • 平台域名只留做「升级 QwenPaw / 重启容器」等管理操作

配套习惯：

  • 审批弹窗出现后立刻处理（5 分钟必超时）
  • 聊天窗口保持前台（Chrome 后台标签会被节流）
  • 每天开新会话，别把上下文堆到百万级
  • 重活直接 ssh root@100.68.168.78，命令行无超时
